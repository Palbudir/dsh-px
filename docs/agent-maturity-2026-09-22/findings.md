## B01 · 默认测试命令在 Windows 沙箱中失败

**分类与证据强度：** 运行兼容；已实测

**重要程度与难易：** P1；难度 4/5；5–10 人日

**观察：** E01/E02 两轮 npm test 均出现 spawn EPERM；同测试使用 --test-isolation=none 通过，应用外默认 runner 也通过。

**原因与边界：** 受限 Windows 子进程管道是官方已记录的约束；仍需确定各测试工具的覆盖面。

**复现：** 在安装版对 fixture 执行 npm test，对照 npm run test:single。

**修复方向：** 诊断具体限制；优先原生受控执行与明确的单命令审批，不关闭全局沙箱。

**验收：** 两种 runner 对相同断言产生一致结果，命令受限时不误报业务测试失败。

**排期：** 下一功能发布的阻塞队列

**关联功能：** [S01](feature-catalog.md#s01)、[M29](feature-catalog.md#m29)

**证据：** [E01](evaluations.md#e01) · [E02](evaluations.md#e02) · [C04](sources.md#c04)

## B02 · 完成交付后待办仍未完成

**分类与证据强度：** 任务一致性；已实测

**重要程度与难易：** P1；难度 3/5；3–5 人日

**观察：** E02 最终答复与 ready_for_review 均称完成；唯一 todo/write 事件仍为 1 进行中、6 待处理。

**原因与边界：** 模型未更新 todo，产品缺少终态一致性核对。

**复现：** 完成多文件修复后比较最终答复、任务进展与 todo 卡。

**修复方向：** 读取原生 todo/交接点/验证状态，交付前自动核对并让 Agent 解释或完成剩余项。

**验收：** 完成、失败、取消三种终态在各面板一致。

**排期：** 第一轮可靠性交付

**关联功能：** [S02](feature-catalog.md#s02)

**证据：** [E02](evaluations.md#e02) · [C01](sources.md#c01)

## B03 · 只读执行也触发交接点过时提示

**分类与证据强度：** 提示噪声；已实测及纯函数复现

**重要程度与难易：** P2；难度 2/5；1–3 人日

**观察：** E02 正常交付流程后就提示记录过时；E08 checkpoint 后单次 read 使 stale=true。

**原因与边界：** 当前设计将任何后续执行视为可能过时；不是数据丢失。

**复现：** 构造 checkpoint → read → 成功结果，调用 reviewEvents。

**修复方向：** 区分只读、修改和验证；未知工具保守标记，但不一律警告。

**验收：** 纯读取不告警，修改后要求重新核验，后续执行仍可追踪。

**排期：** 第一轮低成本修正

**关联功能：** [S05](feature-catalog.md#s05)

## B05 · 兼容编辑器的 view 被统计为写文件

**分类与证据强度：** 归因错误；纯函数已复现

**重要程度与难易：** P2；难度 2/5；1–3 人日

**验收：** 只查看不出现写入标记，真实编辑仍记入。

## B07 · 任务进展默认输出可能过大

**分类与证据强度：** 性能与成本风险；合成负载已测，真实卡顿未证实

**重要程度与难易：** P2；难度 3/5；3–5 人日

**观察：** 80 条最大长度输入/输出的 review 序列化为 297669 字节；每次检查可能重复注入。

**原因与边界：** 默认返回全文片段，而非摘要加按需展开。不能由字节数直接推出 token 或费用。

**复现：** 运行 evidence-probe 的长输出样例。

**修复方向：** 默认紧凑摘要、按需输出、增量事件缓存；先测真实会话性能。

**验收：** 固定信息量下默认响应受预算约束，历史全文仍可获取。

**排期：** 第二轮效率优化

**关联功能：** [S18](feature-catalog.md#s18)、[L21](feature-catalog.md#l21)

**证据：** [E08](evaluations.md#e08) · [C01](sources.md#c01)

## B10 · 审查报告存在未经证实的行为断言

**分类与证据强度：** 模型报告质量；已独立反证

**重要程度与难易：** P1；难度 3/5；3–6 人日

**观察：** E03 声称冻结库存再次使用会抛 TypeError；独立测试正常返回新库存。E04 又错误暗示只读时不能侧证文件不存在。

**验收：** 报告不出现无证据的确定性结果；错误发现被反证后能撤回。

## B11 · 公开网页抓取被本机 DNS/代理路径阻塞

**分类与证据强度：** 本机集成阻塞；已实测并核对解析

**重要程度与难易：** P1；难度 3/5；3–6 人日

**观察：** E10 搜索有效；nodejs.org、raw.githubusercontent.com、GitHub 等抓取报非公网 IP；本机解析 Node.js/GitHub 到 10.100.0.x。

**原因与边界：** 直接抓取的公网地址校验触发；原生代码已有代理路由分支。实际代理配置/继承原因仍待下一轮定位，未认定某代理软件故障。

**复现：** E10 的 web_fetch 调用；系统 Resolve-DnsName 对照。

**修复方向：** 按 DSH 原生 http-proxy 机制打通可信代理路由并增加诊断；保留私网和重定向约束。

**验收：** 公开官方文档抓取成功；故意请求私网目标仍被阻止。

**排期：** 首批本机可用性修复

## B18 · 结构门禁被描述为能力成熟度证明

**分类与证据强度：** 验收范围不清；源码确认；本轮修正文案

**重要程度与难易：** P2；难度 2/5；文档 1 人日；任务回归 4–8 人日

**观察：** verify-capabilities 对比组合树并检查启动，不能证明每项工具或模型工作流能用。

**原因与边界：** 工程结构验证与真实任务验证被混为一个能力平价结论。

**复现：** 阅读脚本对比字段及 boot 流程，对照 E10 抓取阻塞。

**修复方向：** 保留结构门禁，增加安装版正常/异常任务矩阵并限定宣称。

**验收：** 发布说明分别列结构、自动测试、真实任务和未测范围。

**排期：** 本轮文案 + 下一轮回归

**关联功能：** [S15](feature-catalog.md#s15)

**证据：** [C06](sources.md#c06) · [E10](evaluations.md#e10)
