# 当前能力与运行边界

本页描述当前维护代码的功能契约。Pack 与 Desktop 版本以 [products.json](../config/products.json) 为准；可下载安装的版本及已发布变更以 [Releases](https://github.com/Palbudir/dsh-px/releases) 为准。未发布事项见 [路线图](ROADMAP.md)。

## 能力分工

| 能力                                       | 所有者                              | 边界                                                  |
| ------------------------------------------ | ----------------------------------- | ----------------------------------------------------- |
| 模型、对话、工具、权限、计划与历史         | DSH                                 | 不在插件或桌面覆盖层中重写执行与授权                  |
| 文件、编辑器、终端、文件变动及后台任务视图 | DSH 与 dsh-better-sidebar           | 原生与社区服务须实际激活；禁用侧栏会影响依赖面板      |
| 工作工具栏与共享数据                       | dsh-px-workspace                    | 会话统一使用官方侧栏；不再提供另一套会话标签          |
| 产物、引用批注、定时任务                   | artifacts / annotations / schedules | 功能插件分别启停，定时执行需要服务与调度插件运行      |
| 执行记录与按需证据                         | dsh-px-taskflow                     | 工具返回不等于业务成功；工作摘要为可选模型记录        |
| 运行诊断、工作区入口与活动快照             | dsh-px-workbench                    | 使用原生服务；未知任务状态不能视为空闲                |
| 版本与更新                                 | Desktop 更新器与 dsh-px-updater     | Desktop 按签名清单更新；Pack 只提示，由插件管理器安装 |

## 桌面与 Web

- **PX Desktop** 基于锁定的官方 Desktop 源码，拥有本机服务、窗口、重启、退出与应用更新。
- **浏览器页面**可连接同一个服务，共享会话、模型、插件和已保存业务数据。重启或退出服务会影响全部连接页面。
- **dsh web** 加载同一 Pack 时，宿主操作以 DSH 自身入口为准；Pack 不提供重启或停机按钮。
- 未修改的官方 Windows Desktop 曾在 0.2.1 验证；当前主线为 PX Desktop 与 Web，原版客户端后续兼容性不作扩展声明。

“运行与帮助”显示页面载体、原生服务和实际激活的依赖。端口可能因占用改变，不能把固定端口当作应用身份。

当前源码提供 **应用 → 在浏览器中打开**：通过运行中宿主的原生认证链接打开系统默认浏览器，不另起服务。Desktop 退出后，这个浏览器页面也失去服务连接。此入口随 Desktop 0.2.1-alpha.1 交付。

Desktop 保留官方账户界面；官方账户登录与自行配置模型提供商凭据是不同入口。使用可用的 API Key 不要求先登录官方账户。会话统一由官方左侧目录管理。PX 只保留文件、终端、产物等工作工具入口。

## 状态与数据

会话正文由 DSH 持久化。批注与定时配置保存在插件业务存储中；损坏时保留原文件，并可从有效快照恢复。恢复后的定时任务暂停，核对后再启用。

旧版标签布局数据保留，但新版不再显示或修改这套会话标签。未保存的批注和定时表单属于当前窗口，切换面板保留，关闭前应保存。

已保存的用户或助手消息支持选句：选句后的浮层支持直接引用或就地填写批注，“加入对话”先保存批注，再通过原生输入接口追加草稿，不自动发送、不打开侧栏。每个选区独立保留当前窗口的批注草稿；收起后重新选中同一原句可继续。历史管理仍在“引用与批注”侧栏。无法保存、原文变化或输入框不可写时显示错误；已保存的批注可再次引用。选区须属于同一条消息，且对应连续正文；服务端校验原始文本或纯文本 Markdown 投影，保存原始消息摘要。格式化回退最多处理一百万字符；特殊渲染可通过原文编辑器调整。

定时记录区分投递中、已入队、执行中、轮次结束、失败、取消和中断。轮次结束只表示原生执行结算，是否达到任务要求仍需检查输出。服务离线期间不执行，周期任务不连续补发积压。

重启、退出与安装由原生宿主处理。workbench 的活动快照只读，展示当前可见的 Agent、队列、后台任务及已检测到的终端资源。宿主接口不能确认终端与后台任务的完整总数，因此观测为零也不表示服务空闲，不作为停机依据。

## 限制

- DSH 工具权限、文件版本保护及网络限制继续生效。文件版本冲突应重新读取并检查差异，不绕过保护。
- Windows 子进程、项目依赖和第三方插件兼容性取决于具体任务环境；错误需按具体命令归因。
- Windows 受限环境下，部分 Node 测试或构建命令会因子进程输出管道返回 `spawn EPERM`，实际测试可能尚未运行。执行记录可为有完整原命令与工作目录的记录准备一次性授权请求；只追加草稿，发送后仍须原生审批。批准仅作用于该命令，不改变默认权限；拒绝或取消后保持停止。
- 执行记录只包含 DSH 已保存的内容。上游未保存或已截断的输出无法在此恢复。
- 写入路径列表不等于 Git 差异；命令行修改、删除、重命名和人工已有改动要在“文件变动”的 Git 视图中检查。
- 第三方侧栏的自动激活、预览和终端能力受其设置及依赖影响。受浏览器检查器或策略拦截的预览不能直接归因为产品缺陷。

插件清单见 [config/plugins.json](../config/plugins.json)，宿主锁定见 [native-pack.json](../config/native-pack.json)；依赖和扩展规范见 [PLUGINS.md](PLUGINS.md)。
