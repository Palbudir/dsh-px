# 普通 QQ 账号

**设置 → QQ 账号**用于把一个普通 QQ 号接入 DSH-PX。它与“IM机器人”中的官方 QQ 机器人是两种接入方式，不需要 QQ 机器人 App ID。PX 复用社区 OneBot 通道和 DSH 原生会话、工具权限、人格与存储。

## 先准备什么

- 一个交给 Agent 使用的 QQ 账号，以及你自己的负责人 QQ 号。两者不能填反。
- 本机已安装 QQ，手机 QQ 可以完成该账号的扫码和登录确认。
- 一个运行中的 [NapCat Shell](https://napneko.github.io/guide/boot/Shell)；当前兼容验收基线为 [NapCat 4.18.41](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.41)。QQ 客户端与桥接之间的兼容性也取决于 QQ 版本，不能仅凭桥接版本判断所有媒体接口可用。
- 一个已配置、可用的 DSH 模型，以及用于 QQ 任务的独立工作目录。

QQ 与 NapCat 由用户另行安装，Pack 不捆绑 QQ 客户端。桥接占用这个 QQ 账号的电脑端登录；启动前退出**同账号**的普通 QQ 窗口，其他 QQ 账号可以继续使用。扫码、验证码和账号验证由你本人完成。不要把 QQ 密码或二维码发到群聊。

## 配置步骤

1. 按 NapCat 的 Windows Shell 说明启动并登录专用 QQ 账号。保留它的运行进程。
2. 在 NapCat 的网络设置中新建 **WebSocket 服务端**，监听地址填 `127.0.0.1`，选择一个未占用端口，例如 `64327`，消息格式使用数组。设置一个独立的 OneBot 连接令牌并保存。这里用的是 **OneBot 令牌**，不是 NapCat WebUI 密码。
3. 在 DSH-PX **设置 → QQ 账号**填写专用 QQ 号；“授权成员”填写你自己的 QQ 号。添加多个负责人时用逗号分隔。普通成员不需要加入此列表才能聊天。
4. 选择独立工作区和固定人格。没有合适的人格时展开“创建新人格”。“公开介绍”填写群聊可以知道的名字、语气与交流偏好，私人经历和个人资料放在人格私有记忆中。
5. 展开“本机 QQ 桥与连接设置”，地址填写 `ws://127.0.0.1:64327`，令牌与第 2 步一致。**先不开启接入，保存设置**；点击“检查已保存的连接”，确认 QQ 账号及在线状态核对通过。
6. 勾选“开启 QQ 接入”并保存。等状态显示“已连接”后，点击“发测试消息给负责人”。从你的 QQ 私聊回复一句话，收到模型回答才表示完整收发链路可用。
7. 拉入群后，使用真正的 QQ **@ 该账号**再发送问题；不响应“@全体成员”。没有直接提及该账号的群消息不会作为输入调用模型。

地址和令牌需要成对匹配。当前只接受本机 WebSocket 地址；不要将这个服务监听到公网。令牌通过 DSH 原生凭据服务保存，设置页留空表示保留已有令牌。

“QQ 新会话默认模型”仅影响这个渠道后续创建的会话；留空跟随 DSH 默认。它不修改客户端的全局默认模型，也不替换正在使用的会话模型。

## 谁能做什么

| 来自哪里                  | 可以做什么                               | 使用的上下文                                           |
| ------------------------- | ---------------------------------------- | ------------------------------------------------------ |
| 未授权成员私聊            | 普通交流、只读查询明确共享的知识         | 该私聊、公开介绍、项目共享与全局共享知识               |
| 群内任一成员 @            | 普通交流、只读查询共享知识               | 该群、公开介绍、共享知识；不包含人格私有记忆与其他聊天 |
| 授权成员私聊              | 安排本机任务、使用人格私有记忆与原生工具 | 固定人格、该成员的私有任务会话、获准的历史和知识       |
| 授权成员群内 `/task 内容` | 在独立的原生群任务会话执行               | 本群上下文、该群项目共享与全局共享知识；结果留在原群   |

授权根据真实 QQ 发送者编号判定，昵称、群主身份及“我是负责人”的文字不能授予权限。公共聊天没有本机文件、终端或电脑操作工具；它使用独立的原生公共交流预设。不要在普通客户端新会话中手动选择这个渠道管理预设。

“授权成员”允许发起任务，但不会关闭 DSH 的原生工具权限。需要审批的动作仍会询问；本次批准不是永久授权。群任务在原群交付，不自动加入人格私有记忆或其他私聊。执行权限与资料受众分别判断；在群里获得任务权限，不代表群成员可以读取负责人的私有资料。

### 给某个群分享资料

- 临时资料：你先在私聊或客户端找到并核对所需内容，再把选定内容发到群里，并明确说明“这些内容可用于本群”。不要把整个私聊或整个人格记忆作为默认共享范围。
- 长期资料：打开客户端中该群的“QQ 群任务”会话，在 **记忆与知识 → 知识与 Skills → 项目共享**新增经过核对的内容。每个群使用独立的 `groups/<账号>/<群号>` 工作目录，因此项目共享只对应这个群；选“全局共享”则会向所有可使用公共知识的会话开放。
- 原文件：只把本群允许使用的文件复制到该群工作目录，或明确在任务要求中指定可用于本群的文件。原生工具权限仍然适用。群任务的文件发送限制在该群工作目录内，不能通过任意收件人参数发到其他聊天。

公共 QQ 会话不自动注入 Mnemon 原生 Provider 或全局／项目 `AGENTS.md` 快照；共享知识通过受该聊天范围约束的 `qq_public_knowledge` 查询。群任务仍可按用户要求读取群目录中的具体文件，并使用仅限本群的原生历史检索。

普通交流也可以按需读取本群历史和成员信息、使用 QQ 表情、查看或复用本群图片。图片通过原生附件提供给声明支持图片输入的模型；无法取得图片、模型不支持看图或历史不完整时会明确提示，不把图片描述或文件名当作看图结果。群角色和昵称只用于理解交流，任务授权仍按实际 QQ 编号判断。

明确的长期称呼、表达偏好和约定通过 `qq_memory` 保存到该群的项目共享文档，按当前人格区分，并保留原生事件依据；`persona_history` 可找回本群同人格的原始交流。新会话可继续检索，修订旧信息需要当前版本，关闭人格记忆会停止这类读写。群内记录可在现有“记忆与知识”的项目共享范围检查。旧的测试会话若缺少独立工作区记录，应由负责人发送 `/new` 后使用，原历史保留。

日常回复优先简短表达。需要交付长报告、代码或说明时，可用 `qq_document` 将完整正文发送为 UTF-8 文本文件，随后用短消息说明；这只生成当前聊天的交付内容，不授予普通成员读取本机文件或操作电脑的权限。

群任务使用普通原生执行预设，具备原生文件、终端、Goal/Team 与提问能力；普通群交流仍只有公共知识查询和授权任务入口。群任务与群聊天是不同的原生会话：群成员的聊天不会直接插入负责人的执行轮次，负责人用 `/task` 继续补充要求。同一群、同一负责人接续原生任务记录，其他群和负责人的私聊不会合并进来。

## 日常用法

| 命令或操作                  | 行为                                                                                                                              |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 私聊或群内 @ 后直接说话     | 普通交流；负责人私聊可直接安排任务                                                                                                |
| `/help`                     | 查看当前可用命令和权限范围                                                                                                        |
| `/task 要完成的事`          | 负责人发起或继续当前聊天的任务，群内结果留在原群                                                                                  |
| `/status`                   | 查看状态；公共聊天不会显示私有工作信息                                                                                            |
| `/new`                      | 负责人创建该聊天的新会话；旧会话保留，新会话采用当前默认人格与模型                                                                |
| `/stop`                     | 负责人请求取消当前 QQ 会话的回合；群内同时取消本群任务的回合与排队输入。已经发生的外部操作不会被撤销，后台任务仍遵循 DSH 原生规则 |
| `/model`                    | 负责人私聊选择当前会话的同档模型；需要配套宿主的会话选择接口                                                                      |
| `/continue 提供商ID 模型ID` | 负责人私聊新建接续会话，可跨上下文档位；原会话保留，新会话获得有截止点的交接摘要与历史读取范围                                    |

群命令同样需要 @。`/newtask` 新建你在该群的任务会话，采用当前默认人格与模型，保留旧记录；任务仍在运行时应先 `/stop`。群里的 `/new` 只重建交流会话，不删除或清空群任务；任务记录在客户端的“QQ 群任务”会话中查看。跨档切换模型不能直接继续复用旧会话；使用 `/continue`。旧宿主缺少专用接口时会明确提示更新，不能通过修改全局默认模型代替。QQ 不支持 `/model --default`，请在设置页选择 QQ 新会话默认模型。

### 审批和回答问题

群任务的提问和审批发到原群，只接受该任务的授权发起人回答；其他群成员的回答不会生效。

需要确认时，QQ 卡片给出请求编号及完整可显示的操作参数。照卡片发送 `/approve 编号` 批准一次，或 `/reject 编号` 拒绝。普通“yes”“好的”不会被自动当成批准。

模型提问时，如果当前会话只有一个问题卡片，直接回复选项序号或文字即可，多题按顺序回答。同时有多个问题或需要指定题目时，使用 `/answer 编号 题号 回答`。选项可以填序号或完整文字，多选用逗号分隔；也可以填写自己的答案。所有题目答完后一次性交回原生请求。计划审批必须选择卡片给出的选项，避免把含糊的自然语言当成同意执行。这个简化仅适用于问题回答，不会把普通“yes”当成工具审批。

也可以打开 **设置 → QQ 账号 → 待处理请求**完成同一个请求。QQ 与设置页先处理的一方生效；取消、超时或已处理的编号不能再次使用。需要完整展示但内容太长的确认会提示转到原生客户端，不截去参数后要求批准。

## 人格、接续与数据

QQ 创建的原生会话出现在独立工作区中，名称带“QQ 私聊”或“QQ 群”及对应账号／群号，已有手动名称不会覆盖。打开会话后可展开“收到执行请求”查看原始 QQ 消息，并使用原生对话、轨迹和上下文视图核对执行过程。

- 每个群、每个私聊分别绑定原生会话。会话固定人格版本、公开介绍和受众边界；修改默认设置只影响后续新会话。
- 普通聊天不能读取其他群、其他私聊或人格私有经历。未授权成员私聊使用 `visitors/<账号>/<成员号>` 的独立公共资料范围，不共用负责人的私有任务项目。共享知识管理沿用[人格、记忆与工作账本](MEMORY.md)中的四范围规则。
- 授权成员原有私有会话不会在撤销授权后转换成公共历史；重新进入时必须按新的边界创建会话。
- 切换模型和接续复用原生模型目录、分档校验和会话创建。接续不复制运行中的 Goal，也不重复执行旧任务。
- 原生会话是执行记录的权威。QQ 投递回执只用于识别重复消息，不把“入队”冒充“任务完成”。无法确认的投递不会自动重跑，应先核对客户端中的原生任务与原聊天结果。
- 设置保存在原生 profile 的 QQ 成员配置中；人格、历史与知识保存在原有 PX/DSH 存储中。桥接自己的登录与媒体缓存位于 NapCat 目录。不要公开这些目录或把它们提交到仓库。

## 停止、更新与故障处理

**只停止任务**：私聊 `/stop`，或在 QQ 设置中点击“停止当前任务”。群里的 `/stop` 同时请求停止该群的任务和排队输入。这不等于停用渠道，也不撤销已完成的操作。

**停用接入**：等待任务结束，在设置中取消“开启 QQ 接入”并保存。NapCat 是独立程序，不会随该开关自动卸载或退出。要完全离线，再退出专用桥接进程。

**重启与更新**：保持桥接运行，正常重启 DSH-PX 会重新连接并恢复聊天映射。群任务的历史保存在原生会话里，重启本身不自动重新执行请求；负责人在原群发送 `/task` 才继续接入该任务。Pack 和 Desktop 更新按[更新说明](../README.md#更新与数据)进行。不要让两个 DSH 实例同时消费同一个 QQ 号或共写同一数据目录。

| 看到的状态                | 处理方法                                                                                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 等待连接、连接失败        | 确认桥仍在运行，地址、端口和 OneBot 令牌一致；保存后再检查                                                                                                             |
| QQ 账号不在线或账号不一致 | 到 NapCat 完成登录；核对专用账号，不要把负责人账号填到机器人账号栏                                                                                                     |
| 已登录，无法重复登录      | 完整退出同账号普通 QQ 的电脑端，再启动桥；保留其他账号                                                                                                                 |
| 已连接，但没有模型回答    | 检查 DSH 模型凭据、原生任务状态和待处理请求；群消息必须真的 @ 账号                                                                                                     |
| 设置已变化                | 另一个窗口已保存配置；本窗口草稿保留，核对后重新加载，不直接覆盖                                                                                                       |
| 接续记录未能保存          | 检查磁盘和目录可写性，在设置中重试保存；已执行任务不会因重试而自动再次执行。如果提示记录不可读或格式损坏，原文件会保留；恢复记录后重新启用组件，不能用空记录覆盖旧状态 |
| 当前 QQ 成员不是配套版本  | PX 保留用户自行安装的原包和配置；使用 Pack 附带的兼容成员后再启用，见下文                                                                                              |
| 媒体接口失败              | 先验证文字通道，再检查 NapCat/QQ 兼容性；未验证的图片、语音、文件接口不视为可用                                                                                        |

## 独立 Web 与社区成员

Desktop 配套安装 `dsh-px-qq` 功能包和 `dsh-onebot-qq` 独立社区成员。用户自行安装的同名社区包不会被静默替换。当前兼容成员由上游 `0.9.6` 派生为 `0.9.6-px.3`，保留原名称和 BSD-3-Clause 许可；原始来源、摘要及兼容修改记录随包交付。

独立 `dsh web` 先安装聚合 Pack，再从该 Pack 归档的 `package/distribution/` 中取出配套 `dsh-onebot-qq-0.9.6-px.3.tgz`，使用原生插件管理器安装到相同 profile。这个派生版本随 Pack 提供，不要假设 npm 上存在同名版本。原来已安装上游包时，先检查并保留其配置，再由用户明确选择替换；兼容版通过 PX 的“QQ 账号”页配置，不同时显示两套配置界面。

群任务不提供跨渠道 IM 发送、跨聊天原始 API 与定时任务工具；这些需要在负责人私聊或客户端按原生入口配置。群内的模型管理暂在客户端对应“QQ 群任务”会话中使用原生模型选择器；它同样遵守档位限制；该原生客户端选择器仍沿用 DSH 保存全局默认模型的行为，区别于只影响本会话的 QQ `/model` 命令。

具体源码与发行约束见[插件合约](PLUGINS.md)。协议连通、模型回复、本机执行、媒体发送分别验收；文字收发成功不代表 QQ 的全部业务功能已经开放给 Agent。
