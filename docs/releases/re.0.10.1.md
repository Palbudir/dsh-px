# re.0.10.1 · 更新检查与服务状态修正

手动点击“检查更新”曾误清理 Agent 服务心跳，导致工作台在 15 秒后显示离线，而对话、读取文件和产物展示仍能正常运行。该问题在 re.0.10 安装后的进一步复核中确认，原 re.0.9 中也存在。

本修订让手动检查只取消延后的启动检查并调用更新器，服务心跳只在退出时清理。同时修正初始化顺序，避免重置更新桥时丢失当前安装能力字段。

71 项行为测试通过；新增两项同时使用真实文件心跳和更新控制器，覆盖检查成功、网络失败、超过 15 秒继续刷新，以及退出才停止心跳。

隔离实例实际收到 check-shell 请求后观察 20 秒，心跳持续刷新、服务 PID 不变，工作台显示“已连接 / 桌面服务运行中”。开发态的界面只做版本查询，因此这里另外验证了真实桌面检查入口，避免把元数据查询成功算成更新器回归。

Windows/Linux CI 和发布流水线均通过，安装包内部入口、运行时与插件已校验。原安装交付以更新前备份、应用内安装、再次检查更新、持续心跳及旧数据保留为验收步骤；实际结果记录在 [对应 Release](https://github.com/Palbudir/dsh-px/releases/tag/v0.1.0-beta.re.0.10.1) 和本机 `build-test/re101-*`，不公开配置与会话正文。

继承 [re.0.10 的质量整理](re.0.10.md)，详细发现见 [Q24](../quality-2026-09-24/README.md)。未扩展功能范围或改变 DSH 核心版本。
