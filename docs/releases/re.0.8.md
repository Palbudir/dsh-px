# re.0.8 · 任务证据分页与本机网页读取

这一版以具体功能实现为发布标准。目标是准确查看执行、按需取得历史输出，并使本机公开网页读取可用。模型任务质量与主观效率另作观察，不作为这些功能是否实现的替代判断。

## 新功能与修正

1. **执行摘要与历史分页**：任务进展和 `task_review` 默认每页 20 条；工具可调整至 1–50 条。用 `nextBeforeSeq` 查询前一页，界面可前后翻页并返回最新。
2. **按编号读取输出**：`task_evidence` 接受 `callId`，默认 4000 字符，单页上限 8000。`nextOutputOffset` 指向后续段。界面展开执行时才读取正文，并提供“读取后续输出”。
3. **早期证据可引用**：交接点可引用当前会话任何已结算的非内部调用，不再只搜索最近 80 条。伪造、其他会话、取消和未知结果仍被拒绝。
4. **状态和归因准确性**：成功读取的历史错误文字仍为读取成功；`str_replace_editor view` 不列入写入路径；任务进展区分已取消、结果未记录和执行异常。
5. **只读后续操作降噪**：已知读取、搜索、网页获取、交付等操作不会单独使交接点过时；写入与未知副作用仍触发提醒。
6. **读取失败可区分**：会话不存在、损坏、格式不兼容、权限不足、暂时忙和未知故障分别返回稳定错误码。不可通过重复读取修复的错误停止自动重试，并保留手动重试入口。
7. **本机系统代理接入**：没有显式 DSH 代理配置时，外壳将 Windows 已设置的本机静态 HTTP(S) 代理地址传给 DSH。使用原生网页服务和保护机制，不另写下载器。
8. **网页读取检查**：设置 → 运行与帮助 → 本机运行诊断与服务恢复 → 检查网页读取。实际读取 Node.js 与 TypeScript 官方文档，显示状态与正文字符数，不调用模型。

## 使用示例

```json
task_review({"limit":20})
task_review({"beforeSeq":120,"limit":20})
task_evidence({"callId":"从 task_review 取得的编号"})
task_evidence({"callId":"同一编号","offset":4000,"maxChars":4000})
```

上述是工具调用示意，不能把占位编号当作实际证据。阅读不会重跑工具。正文指 DSH 会话已经保存的文本；如果原始工具本身先做了截断，未保存的内容无法由此恢复。文件写入路径清单也不能代替 Git 差异，命令行修改与人工已有改动仍需在文件变动中核对。

## 代理配置优先级与范围

优先级为：启动环境的 `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`（含小写）→ DSH 数据目录 `.env` 中的显式配置 → Windows 本机静态代理自动接入。这里的“优先”意味着已有显式设置时不注入系统值；变量之间的具体合并和回退仍由 DSH 原生机制决定。

- 只自动接入 Windows 已配置的 localhost/127.0.0.0/8/::1 HTTP(S) 代理；不扫描端口、不猜代理软件。
- PAC、SOCKS、带认证的系统地址、远程代理和不完整的按协议映射不自动转换，诊断中明确提示；可继续使用 DSH 原生环境配置。
- 自动接入只继承代理服务器地址，不复制 Windows 高级绕过通配符。现有 `NO_PROXY` 保留，回环地址由 DSH 保持直连。需要特殊绕过策略时使用显式配置。
- `DSH_PX_SYSTEM_PROXY=0` 关闭自动接入，不删除显式配置。代理改变后重启 Agent 服务生效。
- 诊断只显示配置来源，不输出代理凭据。系统代理设置、用户 `.env` 与模型密钥不被改写。

命令工具的 Windows 命名管道限制、完整只读审查模式、todo 与交付终态统一仍在后续排期；本版不宣称解决这些独立问题。命令状态仍有一项边界：持久记录只保留渲染文本时，无法完全区分工具追加的退出标记与命令自行打印的同形标记；API 的 `outcomeSource` 会明确标记这类推断。
