# 后台操作与独立实例

电脑操作按目标已有能力选择通道：网页优先使用独立浏览器，标准桌面界面使用 UIA 或原生控件，特殊应用可选用应用内输入桥。后台模式不会自动回退到占用系统鼠标的前台操作。

## 通用软件

在“电脑操作”开启桌面应用，选择“仅后台操作”。模型先观察窗口，再按元素提供的动作操作按钮、复选框、列表或文本。文本替换使用控件赋值，不用 `Ctrl+A` 模拟替换。界面元素可读取不代表所有动作可执行；操作后仍须观察实际结果。

后台通道不显示另一个覆盖在屏幕上的代理光标。用户切换其他应用不应被当作目标抢焦点；检测到被控应用转入前台时会中断并提示检查。检查不是对任意第三方软件的绝对保证，尤其不能将操作前后的状态核对当作全过程输入隔离。

要让双方互不修改同一份页面状态，使用“独立浏览器”，并开启“后台运行浏览器”。每个会话拥有自己的临时浏览器实例；“PX 专用浏览器”和“接管我的 Edge”包含共享登录或标签状态，不能宣称与用户操作完全隔离。

## 可选应用输入桥

输入桥运行在明确适配的应用实例内，只接收画面观察和有时长的虚拟输入。它不注入系统键鼠、不共用系统剪贴板，也不提供游戏寻路、世界状态查询、命令执行或游玩策略。普通窗口不会因为开启开关就获得这种能力。

当前适配 **Minecraft Java 26.3 / Fabric Loader 0.19.5 / Java 25**。这是可选模组，不是纯原版后台输入，也不适用于 ATM9 或其他 Minecraft 版本。纯原版仍使用已经授权的前台工具。

1. 在启动器中建立独立的 Fabric 26.3 实例，启用版本隔离，先使用独立测试世界。
2. 从本版电脑操作功能包的 `native/minecraft-input/` 目录取出 `px-input-bridge-mc26.3.jar`，放入该实例的 `mods`。同目录的 `manifest.json` 记录版本和 SHA-256；不要复制其他版本的桥接模组。
3. 在这个实例的 JVM 参数中加入 `-Ddsh.px.game.isolated=true`。未提供此参数时模组不启用隔离或网络端点。保持窗口模式；不要把日常实例设为隔离实例。
4. 启动后，在 PX 的“电脑操作”中同时开启桌面应用与“允许独立应用输入桥”。普通访问沿用当前 DSH 会话权限；这不等于允许敏感动作。
5. 模型使用 `computer_list_instances` 找到实例，`computer_instance_state` 读取真实画面，再通过 `computer_instance_input` 执行短动作。每次输入使用本会话最近一次观察的 `frame_id`；完成后重新观察。

Pack 更新不会自动改写启动器或游戏目录。更新输入桥时，关闭该独立实例，以新版 Pack 中的 JAR 替换原文件后再启动；不要同时保留两份同名模组。

隔离实例会屏蔽物理键鼠对游戏内容的输入，因此用户不应在同一个实例中同时游玩。用户仍可关闭或调整操作系统窗口。窗口最小化、停止渲染、系统锁定或显卡重置不属于保证持续可观察的场景；失败时不会改用系统鼠标。

单次输入为 10 毫秒至 10 秒，控制端每 500 毫秒续租。暂停、取消或连接中断后释放虚拟输入，失去心跳约 2 秒后失效；释放由应用线程处理，应用线程卡死时无法承诺精确的墙钟截止时间。未确认释放前不继续输入。应用关闭时停止服务并移除本地连接登记。

连接端点仅绑定本机回环地址，使用随机令牌；登记文件只供当前 Windows 用户读取，不把令牌交给模型。相同 Windows 用户下的恶意程序不属于这个接口的隔离边界。

## 范围

独立实例解决输入与页面状态的隔离，不隔离 CPU、显卡、文件系统或网络。任意只接受前台输入的软件，需要专用适配或独立虚拟机／另一台电脑；当前版本不自动建立虚拟机，也不注入全局键鼠钩子。
