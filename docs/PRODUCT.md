# DSH-PX 产品目标与交付标准

DSH-PX 的目标是在本台电脑上提供成熟 Agent 的工作能力。用户提出需求后，应能看到项目被理解、任务被执行、修改被验证、结果被交付；卡住或中断时知道原因并能继续。Codex、Cursor、Trae Work 是用户提出的能力参照，不作为本项目已经达到同等水平的声明。

DSH 原生插件范式是实现基础。我们负责选型、调校、集成并自制缺失能力；用户无需先理解插件系统。插件数量、开关数量和“自由组装”不是产品验收指标。

## 版本验收：功能为硬标准，效果为软标准（2026-09-23）

每版先声明功能范围和可复现的通过条件。工具/API/界面必须实际接通，正常、失败和边界行为与约定一致，旧会话及配置兼容，正式安装版更新后也能使用；这些是发布硬门槛。功能没有实现，不能由演示、提示词或模型的自述替代。

实际任务成功率、主观实用性、Agent 整体效果和效率作为观察与后续排序依据。保留样例和失败，但不要求先证明难以量化的整体能力提升才交付已经通过功能验收的版本。数据与权限保护、返回状态真实性等明确的功能约束仍按硬标准验证。

## re.0.10：质量与维护

本版以实际使用和日志为依据，处理标签顺序、重复终端、表单草稿、查询反馈、请求来源边界、批注分页与轮询开销。自制区域共用主题色、图标、交互状态和减少动态效果规则；插件清单驱动构建、迁移和产物门禁。明确保留上游行为与验收限制，详见 [质量审查](quality-2026-09-24/README.md)。

## re.0.9：会话工作区

自制 `dsh-px-workspace` 在主界面提供会话标签和文件、终端、产物、后台任务入口，增加可保存的原文引用与批注，以及面向指定会话的定时任务管理。会话导航、输入、文件预览、终端和 Agent 执行仍由 DSH 及已选型的侧栏插件负责。

定时任务属于用户在界面上保存的执行要求，使用原生会话队列，支持冷会话恢复；批注默认只保存，点击引用后才进入草稿。应用退出期间不执行任务。异常投递暂停核对，接收确认与执行完成分开呈现。详见 [本版范围和验收](releases/re.0.9.md)。

## re.0.8：证据分页与本机网页连接

- `task_review` 默认返回最近 20 条摘要，可用 `nextBeforeSeq` 翻阅历史；`task_evidence` 按编号读取会话已保存的输出，支持分段读取。
- 交接点可引用本会话的早期已结算调用；不再受列表的 80 条窗口限制。取消或未知结果仍不能作为已结算证据。
- 历史错误文字不会使读取工具被判为失败；编辑器的 view 不计为写入；已知只读操作不会触发过时提醒。未知操作仍保守提醒。
- 任务进展面板区分取消和未知中断，提供历史页、输出后续段与分级错误提示。主对话的原生状态显示由 DSH 管理，尚未在本版统一改写。
- 外壳在无显式配置时接入 Windows 已设置的本机静态 HTTP(S) 代理，交给 DSH 原生网络机制使用；不写系统设置或 `.env`。运行与帮助新增与 Agent 共用网页服务的实际读取检查。

范围、限制和操作方式见 [re.0.8 说明](releases/re.0.8.md)。下面 re.0.7 小节保留该版设计背景，其中默认窗口与后续执行提醒策略已由 re.0.8 更新。

## re.0.7：任务交接与执行证据

自制 `dsh-px-taskflow` 插件增加会话侧栏“任务进展”与两个 Agent 工具：

- `task_review`：读取当前会话已有的工具调用、结果、文件工具涉及路径和最近交接点；无需 Agent 自行回忆执行结果。
- `task_checkpoint`：记录目标、进展、下一步及实际调用编号。引用必须能在近期日志中找到已结算结果，允许记录失败复现，拒绝编造编号、进行中或未知结果。
- 侧栏通过已装的 `dsh-better-sidebar` 扩展服务注册，沿用 DSH 原生右侧栏。关闭该社区插件会移除面板，但 Agent 工具仍可使用。
- 工作记录直接保存在 DSH 的工具结果事件中，重启后从原会话恢复，不另建任务数据库。冷读取使用官方只读持久句柄，释放句柄，不抢占写入权限。
- 工作流提示要求多步骤实现任务先检查项目约定与既有修改，保留无关改动，使用原工具执行、验证并交付；它不覆盖计划模式或权限策略。简单问答和小修改可以不创建交接点。

“Agent 工作记录”是模型总结；执行记录是系统事实。“已返回”不等于测试通过；“待检查交付”不等于人工验收完成。当前面板显示最近 80 条执行、最多 200 个文件工具路径，长输出截断并提示。命令行造成的文件改动仍应在 Git/文件变动面板审阅；没有 Git 时不能把文件工具路径清单当作完整差异。

任务记录之后发生任何新执行，面板会提醒记录可能已过时。重启不会自动重放可能有副作用的操作，也不会自动启动新的模型请求；用户在原会话继续即可读取交接点。

## 开发顺序

后续按照真实任务失败点推进：先完善修改审阅和验证，再建设项目上下文复用与长任务恢复，最后扩展更复杂的工具集成。每个阶段都需在已安装应用里完成具体任务；不以设置页展示、插件加载成功或一次玩具示例替代成熟度验收。

固定流程：功能分支 → 自动测试与真实任务 → PR → tag 与 Release → 原安装版更新 → 配置、会话与能力复核。当前仅要求本机可用；现有 CI 保留，不扩展分发目标。
