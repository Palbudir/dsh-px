# 产品目标与验收标准

DSH-PX 面向本机项目工作：理解需求、执行任务、验证修改并交付可检查的结果。遇到阻碍时，应用应显示实际状态、保留已保存工作，并提供继续或恢复的入口。

DSH 原生插件架构承载产品能力。整合包负责选择、集成、验证和维护插件；用户按任务使用产品，无需先理解插件组合。插件数量或开关数量不构成成熟度指标。

## 功能契约

| 用户目标     | 产品要求                                                         |
| ------------ | ---------------------------------------------------------------- |
| 理解项目     | 读取项目约定与相关代码，能定位依据与上下文来源                   |
| 完成修改     | 使用实际文件与工具执行，保留无关修改，报告失败与未完成项         |
| 检查成果     | 区分工具结果、模型总结和验证结论，能查看输出、文件与代码变更     |
| 管理会话     | 切换视图不改变任务归属，保存内容可恢复，未保存内容的生命周期明确 |
| 运行后台任务 | 任务有明确所有者，完成、取消、中断与失败可区分                   |
| 安全更新     | 版本来源可验证，活动任务有停机协议，配置与历史保留，失败可恢复   |

## 发布硬标准

每版声明范围与可复现的通过条件。工具、API 与界面实际接通，正常、失败和边界行为符合契约；旧数据兼容；安装包内的运行时、插件及清单一致。

发布前完成独立审查、行为测试、目标 Windows 环境的 Electron 与 Web 回归、升级与恢复检查。已确认的 P0、P1、P2 使用问题不得带入发布。结论应说明测试范围与剩余验证限制，不以有限测试声称所有可能故障已经排除。

源码运行、设置项可见、插件加载成功或模型自述不能替代功能验证。浏览器连接桌面服务也不能替代原生窗口、安装器和退出流程验证。

## 效果观察

真实任务成功率、效率、工具选择与主观实用性用于产品排序。保留明确样例与失败归因，不以少量任务宣称普遍能力提升。数据保留、权限遵循和结果真实性仍属于硬标准。

## 范围边界

当前优先解决 Windows 本机持续使用。跨平台分发、云端服务、多人协作治理和插件商业市场不在当前交付目标中。复杂能力逐步通过 DSH 原生工具、服务、Skills、预设和侧栏扩展实现。
