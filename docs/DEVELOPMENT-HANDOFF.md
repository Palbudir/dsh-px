## 项目结构与边界

- Electron 主进程负责窗口、托盘、运行时物化、进程生命周期和二进制更新。
- 官方 dsh web profile 负责会话、模型、工具、插件组合和设置。继续使用官方扩展机制。
- `dsh-px-updater` 的宿主半边提供 HTTP 端点，客户端半边注册设置分区。
- `update-bridge` 用原子状态文件和白名单请求文件连接插件与桌面外壳。
- 插件两半的 `lib/*.js` 是入库交付物，修改源码必须重建；React 由宿主提供。

## 本轮完成

### 统一更新流程与失败恢复

新增 `src/main/update-controller.ts`，将更新事件与状态转换从主进程入口抽出。
启动检查、托盘手动检查、设置页请求都进入同一个控制器。

- 错误监听在首次检查前注册，避免首轮网络错误只留在日志或卡在检查状态。
- 下载监听只注册一次，重复检查/重试不累积回调和完成通知。
- 检查和下载有并发保护；已有安装包时保留 ready，不被重复检查覆盖。
- 设置页通过 `POST /check-shell` 请求外壳检查并重试；`GET /check` 仍负责版本信息查询。
- 安装只接受 ready 状态，重复点击不重复调用安装器。
- 纠正 `quitAndInstall()` 返回布尔值的误解：它返回 void，不再据此强制退出。
- 提示期间保留 harness，实际 `before-quit` 时才停止服务。
- 安装启动抛错、错误事件、未退出超时均恢复为可重试状态；不强制关闭当前会话。
- 已知安装启动失败后关闭本次进程的退出自动安装，重新下载成功再恢复。
- 退出时清理启动检查计时器、安装计时器和事件监听。

依据：本地 `electron-updater/out/BaseUpdater.js` 与 `AppUpdater.d.ts`；
不把安装启动成功等同于 NSIS 替换全部文件成功。

### 设置页可观测性

- 显示最近检查时间、最新随附核心版本、具体失败原因、下载与安装中的状态。
- 检查时间由外壳保留到下次启动，但不恢复旧进程的 ready/installing 阶段。
- 检查请求失败或只拿到部分来源时，不再显示“已是最新版本”。
- 安装接口的 409/503 不再当作成功，按钮可恢复操作。
- 请求有超时，状态轮询不重叠；连接中断时明确提示并禁用旧的安装入口。
- 打开目录按钮显示“已发送请求”，不把请求文件写入成功当作资源管理器已打开。
- 长错误文字与按钮允许换行。

### 版本与接口校验

- 使用构建期内联的 semver，支持 beta/rc 等完整版本排序，交付物仍无额外运行时包依赖。
- 内联产物保留 semver 的 ISC 许可声明。
- 无效上游版本号按来源失败处理。
- `/install` 增加状态门禁；`/open` 使用精确查询参数校验，拒绝多重参数和伪造后缀。
- 修正 `docs/RELEASING.md` 原有的错误版本比较，规则依据 [SemVer 2.0.0](https://semver.org/#spec-item-11)。
- 同步 README 的发布基线与 package-lock 中落后的根版本信息。
