# Pack 与 Desktop

DSH-PX 使用同一套插件提供 Agent 工作能力。Pack 是插件整合包，Desktop 是预装 Pack 的 Windows 客户端。浏览器连接同一 DSH 服务时使用同一套插件与会话，不是另一份产品实现。

## 当前状态

开发版本采用独立的 Pack/Desktop 身份及版本校验，四个自制插件暂时共同使用 Pack 版本。当前桌面仍是原有外壳，运行时仍固定为 DSH 0.1.5-rc.2；官方桌面源码适配尚未交付。版本拆分不表示已支持官方 0.2 宿主。

[产品清单](../config/products.json) 记录 Pack、Desktop、接口代际、宿主范围和当前支持的入口；[插件清单](../config/plugins.json) 记录运行时及组合成员。构建会核对两者与实际包版本。完整性清单 schema 3 必须包含产品身份，旧装配目录需要重新 stage，不能把旧二进制改写版本后复用。

## 版本规则

双方使用 `0.x.y`，可附加 `-alpha.N` 等预览标识。`x` 是 PX 接口兼容代际，`y` 是各产品的独立迭代次数。Pack 0.2.4 可以与 Desktop 0.2.1 配合，但 Desktop 每次构建必须锁定一个确切 Pack 版本。

需要双方配合的破坏性接口变化提升共同代际。新增兼容功能、修复或桌面资源调整可独立提升版本。共同代际是版本约束，不替代接口能力检测；当前尚未引入新的动态协议协商。官方 DSH 版本独立核验，不通过 PX 的中间版本号推断兼容性。

数据格式版本与接口代际分开。当前数据格式标识 1 表示既有 PX 存储组合，不改写各插件已有的内部存储标识，也不授权自动降级或转换会话。

## 数据所有权

同一数据目录由一个 DSH 服务负责管理；桌面和浏览器可以同时连接它。不同服务实例默认使用独立目录，避免重复调度任务、并发迁移和配置覆盖。两个桌面宿主连接同一外部服务的模式需要另行验证，不能默认支持。

仅调整 Desktop 版本不会触发插件 profile 迁移；Pack、宿主、运行时或受管内容变化会改变迁移身份。迁移继续使用独占锁、停机切换及现有事务恢复，保留第三方配置和明确禁用项。

## 升级实施顺序

官方源码版 Desktop 首次交付采用并行安装：独立应用身份、安装目录和数据目录，只导入现有数据的副本。通过实际任务与更新验证后，再决定是否替换原客户端；预览安装不覆盖日常实例。

1. 独立版本与产品身份贯穿清单、装配、启动、迁移、载荷检查和版本页面。
2. Pack 制品及产品专属更新索引；校验来源、摘要、兼容性与错误产品拒绝路径。
3. 迁移到官方插件接口，分别验证 Web、官方客户端与 PX 客户端；未通过的入口不加入支持声明。
4. 基于锁定官方源码维护桌面资源、更新和必要桥接；复用同一 Pack。
5. 完成安装、数据迁移、失败恢复及精确提交独立审查，再发布。

现有发布器仍只负责 Desktop，Pack 不得经它发布或占用旧客户端读取的 Latest。独立 Pack 通道及新桌面安装策略完成前，不提升线上更新指针。历史标签与资产保持不变。

## 原生 Pack 候选构建

原生宿主的候选依赖固定在 [native-pack.json](../config/native-pack.json)。先运行 `npm run build:plugins`，再运行 `node scripts/run.mjs build-native-pack build-test/native-pack-candidate --candidate`；输出目录必须不存在。`--candidate` 只用于隔离验证，不表示已通过发布门禁。省略该参数时，构建器要求原生宿主版本与产品清单一致。

构建器从固定来源获取侧栏插件，核对完整归档 SRI 后应用认证补丁；自制插件只复制声明的发行文件。可用 `--sidebar-archive=<文件路径>` 复用已下载归档，仍执行相同的完整性校验。生成的 tgz 可通过原生插件管理器安装。成员使用包内真实文件入口，保留各自的客户端元数据，避免首次动态启用依赖尚未刷新的嵌套包解析表。
