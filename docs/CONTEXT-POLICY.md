# 模型窗口与会话接续

PX 依据模型声明的上下文容量选择注入档位。容量指输入、输出等共享的窗口上限，不是本轮还可输入多少内容。

| 声明容量               | 档位                     | 默认注入方式                                                 |
| ---------------------- | ------------------------ | ------------------------------------------------------------ |
| 不超过 65,536 tokens   | 最低限度                 | 保留人格职责和必要规则；少量参考记忆，账本与交接原文按需读取 |
| 65,537～262,144 tokens | 简略                     | 提供更多参考记忆和交接摘录，超出部分仍按需读取               |
| 超过 262,144 tokens    | 完整                     | 使用有界的完整 PX 参考上下文；不会自动装入全部知识库与历史   |
| 未声明                 | 最低限度，并标记“未声明” | 使用保守的注入与输出预算；不代表模型已确认支持某个容量       |

模型设置应填写实际服务支持的窗口容量。自定义路由未填写时，适配器猜测的容量不作为 PX 的容量声明。改了服务端上下文配置，也应同步修改客户端模型配置。

## 会话内选择模型

新会话首次准备模型请求时固定档位。还没有请求的新会话可以自由选择起始模型。已有会话依据其持久记录判断档位，重启不解除绑定。

同档模型可切换，但“同档”不代表容量相等。切到较小窗口时会检查现有上下文与输出预留是否能放入；不能放入时先压缩，或另建接续会话。执行中的轮次结束或停止后才能更换模型路线。

跨档时，模型选择器提供“新建接续会话”：保留人格与工作区，沿用有界历史交接机制。原始会话仍可查找，原会话草稿留在原处。新会话不会自动发送消息、恢复 Goal、重放工具调用或复制隐藏推理。

0.8 保留原生模型选择器及其标签扩展。宿主拒绝跨档切换后，PX 从原生模型目录的失败状态提供接续入口；`/model` 使用同一目录，也会显示该提示。取消接续时原模型不变。

PX Desktop 0.7 及其提供的 Web 页面，在原生模型选择提交前统一校验；`/model` 和直接接口同样受约束。独立、未适配的官方宿主没有该钩子，只能提供 PX 选择器提示和请求前检查，不能声称已经完整拦截原生选择。

## 注入与压缩

人格职责、权限规则和工具合约保持完整。PX 参考记忆按完整条目选入，省略部分可用 `persona_memory` 读取；历史用 `persona_history` 找回；大账本通过 `task_review` 读取，并以 `task_state` 核对原生 Goal／Team。四范围知识继续由 Mnemon 按需检索，不常驻复制文档正文。第三方额外注入仍受其自身配置控制。

每个请求的输出预留按实际容量计算，保留更严格的已配置输出上限。原生压缩仍负责摘要、保留范围、重试与持久事件；PX 只将固定的输出、摘要与余量配置限制到当前窗口可用的范围。不会为切换档位另写一套压缩引擎。

最低档不再额外把原生默认触发点提前到 75%。仍保留用户配置的更低阈值，并由原生引擎同时扣除回答预算与安全余量。自动压力检查若只选中了一个不大于摘要预算的旧压缩摘要，则不再调用模型反复改写它；有新增内容、摘要仍较大、手动压缩或真实超限恢复时，继续由原生引擎处理。窗口声明与估算不扩大真实模型容量，也不保证每份过大的新输入都能被压缩到可用范围。

原生 token 计量仍是估算与供应商回执的组合。未知容量、服务端额外提示词或供应商容量声明错误，仍可能导致超限；此时应修正配置，不能通过放大客户端数字增加服务端容量。
