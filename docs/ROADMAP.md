# DSH-PX 路线图

目标是在 Windows 本机交付可靠的 Agent 工作能力。近期以运行正确性、升级恢复和交互收敛为主，暂缓增加新的复杂功能。

本页是唯一的当前优先工作入口。能力规格保存在 [100 项分阶段目录](roadmap/catalog.json)；目录中的重要程度表示产品排序，不表示当前存在同等级缺陷，也不代表所有能力已实现。已发布变化见 [版本记录](releases/README.md)。

## 当前基线与维护重点

当前基线是 Pack / Desktop `0.3.3-alpha.1`，基于锁定的 DSH `0.2.0-rc.2`。产品形态为插件整合包与预装整合包的官方源码衍生 Desktop；浏览器复用同一套插件。旧外壳的历史功能和发布记录不代表当前宿主职责，当前边界以 [STATUS.md](STATUS.md) 为准。

| 工作               | 归属                     | 当前行为与持续验收边界                                                             |
| ------------------ | ------------------------ | ---------------------------------------------------------------------------------- |
| 定时任务与完成通知 | workspace / 原生 DSH     | 保留入队与原生终态关联；验证慢投递、取消、恢复与重复执行                           |
| 活动诊断与宿主退出 | workbench / 官方 Desktop | 插件仅提供已观察范围的活动快照；退出和重启归宿主，观测为零不代表空闲               |
| 安装与升级恢复     | Desktop 装配             | 核对真实安装器、来源与 Pack 清单；保留用户声明、禁用项和损坏原件，限制恢复副本数量 |
| 两种产品的更新     | Desktop / updater        | Desktop 优先差分并验证完整结果；整个 Pack 独立更新，启动失败回退前一组合           |
| 长历史与存储故障   | taskflow / workspace     | 分页读取有界；插件存储故障不牵连正文，恢复不重复执行任务                           |
| 工具栏、草稿与侧栏 | 客户端插件               | 切换保留输入；多窗口冲突明确提示；缺少依赖时显示实际限制                           |
| 显示与交互         | 客户端插件               | Web 与 Desktop 分别检查缩放、窄窗口、键盘、主题与减少动态效果                      |
| 审查与发布         | CI / 维护者              | 候选提交做一次独立 DS Flash 审查；普通 CI、来源校验、实际安装与更新验收            |

已确认 P0、P1、P2 问题须先修复并复核。验证环境限制和未复现的历史现象单独列入后续验证，不写成已解决缺陷或通过结论。

## 下一阶段

插件展示与发行分层见 [插件分层与组合发行](PLUGIN-DISTRIBUTION.md)：以 PX Desktop 配套开发为主，基础组件与可选能力包分层，持续验证热启停、旧包迁移、选句批注和组合更新。

当前主线为 [Pack 与 Desktop](EDITIONS.md)。近期优先处理以下明确缺口：

1. 跟踪下一代官方插件合约与自动化能力；升级前验证功能插件启停和数据保留。
2. 维护旧会话导入流程与原生索引整理；来源保留、目标不覆盖、旧定时任务暂停。
3. 按真实使用反馈修复交互和升级问题，逐个验证社区插件兼容性。

每次产品发布按变更范围完成 CI 构建、实际安装、签名更新和 Web / Desktop 回归。纯文档或维护工具清理不重发未改变的产品二进制。

| 阶段   | 规格数 | 优先方向                                                      | 进入条件                                   |
| ------ | -----: | ------------------------------------------------------------- | ------------------------------------------ |
| 短期   |     30 | 本机执行可靠性、状态与证据准确、项目约束、只读审查、独立验证  | 以当前原生 Pack 为基线；先解决具体失败场景 |
| 中短期 |     30 | 项目上下文、变更审阅、工作树与 PR、任务恢复、浏览器和文档产物 | 有稳定的任务、权限和结果合约               |
| 长期   |     24 | 大项目、多小时任务、长期存储、持续集成与故障恢复              | 有可比较的真实任务和长期运行数据           |
| 远目标 |     16 | 复杂自主工作、电脑操作、可复用流程和跨任务协作                | 已证明实际收益，并具备清晰恢复与监督边界   |

专项验证继续关注 Windows 子进程限制、文件版本保护触发条件、原生计划终态与第三方面板自动切换。使用隔离样例定位实际机制；在证据不足时不绕过保护，也不先添加另一套任务状态体系。

## 排序与完成规则

- 优先修复阻碍真实工作的错误，再改进清晰度和操作成本，最后扩展能力。
- 每个进入开发的项目声明归属、依赖、范围及验收条件；实现效果通过真实任务观察。
- 范围、验收、独立审查与对应发布记录齐备后标记已交付，回归要求纳入持续维护。
- 当前不投入跨平台分发、云端部署、多人治理或插件商业市场。
