# DSH-PX 路线图

目标是在 Windows 本机交付可靠的 Agent 工作能力。近期以运行正确性、升级恢复和交互收敛为主，暂缓增加新的复杂功能。

本页是唯一的当前优先工作入口。能力规格保存在 [100 项分阶段目录](roadmap/catalog.json)；目录中的重要程度表示产品排序，不表示当前存在同等级缺陷，也不代表所有能力已实现。已发布变化见 [版本记录](releases/README.md)。

## 当前维护重点

下列项目进入维护验收，正式发布前仍须完成独立审查及目标环境检查。

| 工作                     | 归属                 | 当前状态   | 发布验收条件                                                          |
| ------------------------ | -------------------- | ---------- | --------------------------------------------------------------------- |
| 定时认领与最终执行关联   | workspace            | 待发布验收 | 慢投递、暂停、删除、改时间不重复触发；入队与原生终态准确关联          |
| 活动任务停机与恢复       | 桌面 / workbench     | 待发布验收 | 前台、子 Agent、后台命令与排队输入纳入协调；超时及桥缺失可恢复        |
| 运行时与插件事务升级     | 装配 / 桌面          | 待发布验收 | 实际版本与清单一致；完整准备后切换；失败重试不破坏原配置和会话        |
| 更新回执与实例身份       | 桌面 / updater       | 待发布验收 | 陈旧状态不能假连接；动作绑定当前实例和请求编号；失败与取消有终态      |
| 长历史与存储故障隔离     | taskflow / workspace | 待发布验收 | 分页和增量读取有界；存储损坏不牵连正文和产物；恢复保留损坏原件        |
| 草稿、标签布局与依赖降级 | 客户端插件           | 待发布验收 | 未保存内容不被切换覆盖；内存有界；端口变化恢复布局；缺依赖可诊断      |
| 显示、文案与键盘操作     | 客户端插件           | 待发布验收 | 宽窄窗口、缩放、全屏、主题、键盘与减少动态效果通过实际界面检查        |
| 独立审查与发布来源约束   | CI / 仓库维护        | 待发布验收 | 当前 SHA 的质量检查与独立审查都通过；失败关闭；发布来源和版本顺序受控 |
| 文档、载荷与仓库信息     | 文档 / 发布          | 待发布验收 | 使用说明与实现一致；发布载荷无凭据或运行数据；仓库信息与发布资产一致  |

已确认 P0、P1、P2 问题须先修复并复核。验证环境限制和未复现的历史现象单独列入后续验证，不写成已解决缺陷或通过结论。

## 下一阶段

| 阶段   | 规格数 | 优先方向                                                      | 进入条件                                 |
| ------ | -----: | ------------------------------------------------------------- | ---------------------------------------- |
| 短期   |     30 | 本机执行可靠性、状态与证据准确、项目约束、只读审查、独立验证  | 当前维护版完成验收；先解决具体失败场景   |
| 中短期 |     30 | 项目上下文、变更审阅、工作树与 PR、任务恢复、浏览器和文档产物 | 有稳定的任务、权限和结果合约             |
| 长期   |     24 | 大项目、多小时任务、长期存储、持续集成与故障恢复              | 有可比较的真实任务和长期运行数据         |
| 远目标 |     16 | 复杂自主工作、电脑操作、可复用流程和跨任务协作                | 已证明实际收益，并具备清晰恢复与监督边界 |

专项验证继续关注 Windows 子进程限制、文件版本保护触发条件、原生计划终态与第三方面板自动切换。使用隔离样例定位实际机制；在证据不足时不绕过保护，也不先添加另一套任务状态体系。

## 排序与完成规则

- 优先修复阻碍真实工作的错误，再改进清晰度和操作成本，最后扩展能力。
- 每个进入开发的项目声明归属、依赖、范围及验收条件；实现效果通过真实任务观察。
- 范围、验收、独立审查与对应发布记录齐备后，才从当前维护表移出。
- 当前不投入跨平台分发、云端部署、多人治理或插件商业市场。
