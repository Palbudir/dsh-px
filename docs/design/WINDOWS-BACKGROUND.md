# Windows 后台操作与跨屏支持方案

调研基准：2026-10-18。状态：候选方案；尚未宣称任意窗口、全屏游戏或多显示器全部通过。

当前候选已采用固定 0.28.0 的独立原生 EXE，经官方 SDK 的私有进程生命周期接口连接。发行时校验上游压缩包与各个可执行文件摘要，并将文件随电脑操作功能包分发；运行时不临时下载驱动。0.36.0 仅用于对照验证，没有直接升级产品依赖。

实际对照发现嵌入式路径可能截出不完整的高 DPI 窗口，而同版本独立进程能取得完整画面。跨 Windows 虚拟桌面的截图也需要单独验证，不能与多物理显示器混称。“不在当前桌面”不等于最小化。

原生 UIA 的控件 `Invoke` 在跨虚拟桌面时可能切换桌面或焦点，即使调用者没有显式前置窗口。此类行为不符合后台约定。候选已将跨虚拟桌面操作限定为经过验证的传统 HWND 按钮和文本框定向消息，并检查控件类型、窗口归属、快照与超时；不向模型开放任意窗口消息。普通后台动作前后核对前台窗口，发现意外切换时暂停控制。游戏的定向消息连续操作尚不可靠，首轮仍按原版前台模式验收。

## 分开验证的能力

“不在前台”可能指被遮挡、在另一块显示器、在另一虚拟桌面或已最小化。这些状态不同。第二块显示器也不是独立的键鼠焦点；把应用移过去，不会自动获得另一套前台输入。

分别验证窗口发现、准确截图和目标输入。截图正确不能证明输入生效；进程存在不能证明工具能找到窗口；输入返回成功不能证明目标已经变化。比较显示模式时固定显示器，比较显示器时固定窗口模式，避免同时改变变量。

## 推荐顺序

1. **先核对执行环境与 DPI。** 让独立驱动报告交互会话、显示器列表、物理分辨率、虚拟桌面原点和 DPI 感知方式，与宿主进程视角对照。不修改用户的系统缩放配置。
2. **采用官方独立 Cua Driver。** 旧版 Node 子进程中的 `CuaDriver.create()` 仍属于嵌入式原生库路径。候选已改为启动固定版本、带 PMv2 清单的原生 EXE，并通过官方 SDK 连接自己的进程端点。同版本 DPI 对照已复现旧路径裁剪及独立模式完整捕获；后续版本升级继续复核这个差异。
3. **按窗口取帧。** 优先复用驱动的 Windows.Graphics.Capture（WGC）路径。必要时补充微软 `CreateForWindow(HWND)` 参考实现。后台模式不得把桌面矩形裁剪所得的遮挡物当作目标窗口画面。
4. **按应用技术选择输入。** 普通控件优先 UIA，浏览器复用 Playwright/CDP，支持定向消息的控件使用受验证的窗口消息。需要真实键鼠焦点的应用明确报告需要前台，不暗中切换。
5. **游戏单独验收。** Minecraft 26.3 的持续按键、相对视角和输入释放按[游戏方案](GAME-CONTROL.md)验证。原版共享桌面上的完全后台控制仍需证明；若通用接口不足，再比较独立实例或明确批准的游戏输入桥接方案。

| 候选                                        | 用途                                                 | 限制与取舍                                                             |
| ------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------- |
| Cua Driver：当前 0.28.0；隔离评估 0.36.0    | 首选桌面驱动，继续复用窗口、截图、UIA 和现有输入合约 | 原生独立进程与嵌入式模式分别测；新版不代表所有 Windows 问题已修复      |
| Microsoft WinApp CLI 0.7.1／UIAutomation 库 | UIA 查询、Invoke、SetValue 的独立对照实现            | 注入类动作要求前台；截图可能恢复或前置窗口，不能直接当成后台截图承诺   |
| Windows.Graphics.Capture                    | 按 HWND 采集目标帧，作为跨屏与遮挡截图的优先实现     | 最小化、停止渲染、独占全屏和 GPU 后端分别验证；保留捕获失败原因        |
| OBS Window Capture／Game Capture            | 对照验证窗口和 DirectX/OpenGL 游戏的画面能否持续获得 | 是捕获方案，不提供游戏输入；不默认把完整 OBS 装进 Pack                 |
| pywinauto／FlaUI                            | UIA 能力不明确时的测试辅助                           | 普通控件方法有用，不能把模拟物理点击当作后台输入，也不必重复引入到产品 |

0.36.0 npm SDK 和官方 Windows 原生发行资产已存在；当前产品依赖仍锁定 0.28.0，尚未直接替换。上游 #2015 的副屏 UIA 坐标问题仍开放，必须用实际机器验证。

## 接入方式

保留 DSH 原生工具、审批、取消和 PX 的 `DriverLike` 适配层。驱动执行方式可以从嵌入式库调整为受控的独立原生进程，通过官方 SDK 连接；不再实现另一套 Agent 循环。

原生进程使用 PX 独占的端点与运行目录，只管理自己创建的进程，不接管或关闭用户已经运行的 Cua 服务。固定 SDK／原生二进制版本与摘要，验证连接、取消、退出和异常恢复。新版工具参数、截图有效性及实际投递方式先做合约对照，不能仅替换依赖版本号。

授权仍绑定会话和窗口。普通动作复用已获授权，窗口变化、暂停、撤销和驱动重启后重新核对。后台调用不得自动回退到占用前台的输入方式。

观察结果应区分：准确目标帧、仅元素树、过期帧、最小化无帧、捕获失败。PX 已增加对驱动明确标记 `screenshot_frame_valid: false` 的处理：不把该图片交给模型充当目标截图，并说明限制。没有这个标记也不能凭空证明图像正确，仍需真实验收。

统一记录坐标属于窗口图像、客户区还是虚拟桌面。处理副屏负坐标、跨屏移动和不同缩放率时，不重复缩放 `GetWindowRect`／DWM 坐标。动作前重新核对窗口归属与图像尺寸。

## 最小对照实验

固定同一应用、窗口和版本，依次测试：

1. 主屏窗口化、可见。
2. 副屏窗口化、可见。
3. 同一窗口被另一个测试窗口完全遮挡。
4. 主副屏来回移动，分别使用现有缩放设置。
5. 最小化与恢复。
6. 无边框全屏、独占全屏分别记录。

依次比较 0.28 嵌入式、0.28 原生独立模式、0.36 原生独立模式；先控制执行方式这个变量，再控制版本变量。Microsoft UIA／WGC 或 OBS 仅用作必要的独立对照。

普通应用至少检查按钮、文本输入、列表与滚动，验证目标内容改变而用户前台窗口、输入焦点与鼠标未被占用。游戏检查目标帧持续变化和实际移动／转向，不以菜单能点击替代游玩验收。每个测试记录支持、不支持或未测；只有通过的组合进入产品能力说明。

若后台输入依赖目标应用自身支持而无法实现，保留读取能力并说明具体动作限制。若要让模型玩游戏而用户同时使用宿主键鼠，可评估独立计算机／虚拟机中的游戏实例；Windows 虚拟桌面或单纯移动显示器不等同于独立输入会话。安装模组、建立虚拟机等会改变运行方式的步骤另行确认。
