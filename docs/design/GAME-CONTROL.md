# 游戏电脑操作：Minecraft 验收目标

状态：通用驱动与输入执行器已进入真实任务验收，尚未完成自主生存流程验收。本文件不表示当前版本已经可以独立完成 Minecraft 生存流程。普通桌面与浏览器能力继续遵循 [电脑操作](../COMPUTER-USE.md) 的现有规则。

Minecraft 是通用电脑控制能力的综合测试基准。持续按键、组合输入、相对鼠标、窗口识别和中断释放进入通用输入层，不以游戏名称限定这些工具。首轮游戏验收使用原版前台模式；不以一次后台菜单点击成功承诺完整后台游玩。

## 通用能力与任务能力

验收分别回答两个问题：驱动是否准确执行了动作，Agent 是否完成了用户任务。截图返回、输入成功、模型自述均不能单独证明任务完成。通用能力先在可测量的控件中验证，再在真实应用中复核；游戏用于检验无元素树界面的视觉闭环、连续控制和长任务恢复。

| 层次       | 普通应用验证                         | 游戏验证                           | 判定依据                                     |
| ---------- | ------------------------------------ | ---------------------------------- | -------------------------------------------- |
| 发现与观察 | 窗口身份、遮挡和虚拟桌面、文字与图像 | 菜单、背包和三维场景               | 正确目标的实际画面，区分隐藏与最小化         |
| 精确操作   | 按钮、文本框、悬停、滚动与拖动       | 物品栏点击、转向、持续与组合输入   | 目标状态发生预期变化，不凭调用返回判定       |
| 判断与纠错 | 错误提示、失败重试、内容核对         | 触及距离、障碍绕行、物品名称与数量 | 应用自己的文字或可核对的状态；失败后改变假设 |
| 连续性     | 暂停、重启、恢复同一工作             | 分轮采集与制作、压缩后接续         | 任务进度与当前画面一致，不重放旧动作         |
| 中断       | 失焦、取消、执行器异常               | 持续移动或挖掘中停止               | 真实输入已释放，下一步重新观察               |

物理多显示器、Windows 虚拟桌面、窗口遮挡分别记录，不相互代替。一次应用通过也不扩展为所有应用支持。模型误认物品、数量或完成状态须保留为失败记录；独立复核纠正后的任务才能标记通过。

## 目标与边界

在可见游戏画面上完成持续移动、转动视角、挖掘、放置、背包与合成等操作，随后通过真实短任务验证模型的观察、执行与恢复能力。首个验收目标固定为 Minecraft Java 26.3；先验证独立测试世界，再扩展模组整合包。

第一阶段以获得焦点的游戏窗口为目标。窗口后台投递、最小化后截图与游戏真实输入状态须分别实测；普通应用的后台点击成功不能作为游戏后台输入可用的依据。游戏输入接口可用，也不等于模型具备实时战斗或独立通关能力。

跨显示器、遮挡捕获与后台输入的工具选型和对照实验见 [Windows 后台操作方案](WINDOWS-BACKGROUND.md)。不能因一次窗口发现失败，就把原因归为全屏；显示器位置与显示模式必须分别控制变量。

## 输入与观察

| 能力           | 实现要求                                                 | 验证方式                                                     |
| -------------- | -------------------------------------------------------- | ------------------------------------------------------------ |
| 持续按键和鼠标 | 带时长的按下与释放；支持 W、跳跃、潜行、攻击等并行状态   | 观察移动距离、完整挖掘一次方块、停止后的角色状态             |
| 相对视角移动   | 用相对位移表达左右、上下转动，不依赖绝对桌面坐标         | 指针捕获开启时持续转向，验证方向与灵敏度，不能只看输入返回值 |
| 短动作序列     | 本地执行有上限的时序动作；模型不必为每个按键转换发起请求 | 同时前进、跳跃和转向；核对动作总时长与实际结果               |
| 游戏画面       | 复用截图能力，明确帧时间、尺寸和是否过期                 | 游戏场景、菜单和背包分别检查黑屏、冻结帧、缩放与全屏变化     |
| 中断恢复       | 暂停、取消、失焦、退出和进程故障都结束本次控制           | 核对按键已释放；恢复后先重新观察，不重放旧动作               |

动作默认建议 100～500 ms、单次上限 10 s。需要持续挖掘等动作时才延长时长；每段结束后观察，不把会重置挖掘进度的反复松开视为等价操作。相对鼠标量是输入位移，最终屏幕距离或游戏转角受系统与应用设置影响。测量截图、驱动投递、模型决策和完整观察循环的延迟，分别记录中位数与高分位数。不能只报告模型生成速度。

## 控制会话

普通桌面与游戏统一采用会话和窗口授权，授权后普通动作不逐次询问，复用 DSH 原生确认与取消信号。游戏额外需要有界输入动作及持续按键的释放机制；不是另开一套权限体系。

授权绑定 DSH 会话、具体进程与窗口，不能仅凭 `javaw.exe` 名称识别 Minecraft。界面显示当前目标和停止按钮；授权不会因重启自动恢复。游戏窗口失焦、动作期限到达或暂停时结束正在持有的输入，重新控制前先核对窗口与画面。等待确认期间不持有输入。

输入执行器只接受有界动作，不提供任意脚本入口。持有状态、释放和看门狗运行在本地，模型只负责发起动作及观察结果。执行进程退出时，独立看门狗负责释放本次操作持有的输入；不能把“杀死驱动进程”当成“按键已释放”。释放操作不额外按 Esc、不切换窗口、不重放动作。人工抢占和焦点变化后停止继续投递。

目标窗口识别、停止行为与最小化限制先经过无游戏的输入测试窗口验证，再进入独立游戏世界。不得用现有用户存档进行故障注入。

## 实现优先级

1. 核对当前固定 Cua Driver 的 Windows 工具合约，优先复用截图、窗口识别和已有可用输入。
2. 对未覆盖的持续输入和相对移动，评估基于 Windows `SendInput` 的小型独立执行器；先用测试窗口验证按键状态、组合动作和退出清理，再决定交付实现。
3. DSH 继续负责工具调用、确认、会话、Goal／Team 与账本。游戏控制会话只保存输入授权与执行状态，不建立另一套 Agent 循环。
4. 游戏技能描述操作策略、观测方法及恢复步骤；输入可靠性必须由驱动保证，不能只依赖提示词。

## 分级验收

- **输入通过**：持续行走、相对转向、挖掘、放置、跳跃组合、快捷栏切换、背包点击均由游戏内实际变化证明；取消与失焦后无卡键。
- **基础游玩通过**：真实模型在独立世界完成采木、合成基础工具、采集石头、搭建简单掩体；遇到失败能停止并重新观察，保留任务进度。
- **持续游玩通过**：多轮压缩、暂停与恢复后仍能正确继续；记录死亡、卡住、错误动作和人工介入，不能只截取成功片段。
- **进阶目标**：战斗、导航、模组界面与通关单独制定任务和通过条件，基础游玩通过不自动代表这些能力通过。

## 来源

- [固定的 Cua Driver SDK](https://github.com/trycua/cua)：仓库使用 `@trycua/cua-driver` 0.28.0，复用窗口发现、捕获和常规动作；有界持续输入由 PX 执行器补充。
- [Minecraft Java 26.3 发行说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3)：26.3 改用 SDL3 处理窗口和输入，不能沿用旧版 GLFW 的后端假设。
- [Cua 指针工具](https://cua.ai/docs/cua-driver/reference/mcp-tools/pointer)：当前文档把独立鼠标按下、释放工具标为 Linux，不能外推到 Windows 固定版本。
- [Windows SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)：提供键盘和鼠标输入事件；受完整性级别约束，且不会自动重置已有按键状态。
- [Windows MOUSEINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-mouseinput)：区分鼠标按下、释放与相对移动；位移与实际游戏视角关系须实测。
