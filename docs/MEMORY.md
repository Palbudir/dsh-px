# 人格、记忆与工作账本

在工具栏打开“记忆与知识”，可以管理人格私有记忆，或进入项目知识页面。两者分别保存：人格决定协作方式与个人约定，项目知识供同一工作区的会话共同检索。新人格从空记忆开始，不复制其他人格的条目，也不会隐藏共享的项目资料。

## 人格选择

人格与 DSH 的标准、创造等能力模式分别管理。人格改变协作方式，模型、工具和权限仍由原生会话控制。切换或编辑从下一轮生效，不改变正在运行的一轮。选择随会话保留；新建普通会话使用默认助手，分叉会话继承父会话的人格选择。

删除人格会同时删除其记忆，使用它的会话从下一轮恢复默认助手；已有会话正文保留。切换人格不会删除历史消息，因此不能把同一会话内的角色切换当作历史隔离。需要完全不同的聊天背景时，请新建会话。

## 保存和使用记忆

可以在面板中写入、编辑或忘记条目，也可以明确告诉 Agent：“记住本目录使用 pnpm”“修改之前的约定”“忘记这条记忆”。Agent 使用 `persona_memory` 工具读取当前版本后保存变更。

- **本目录**：仅此人格在相同规范化工作目录中使用；暂不自动合并 Git worktree 或不同目录。
- **此人格通用**：此人格在不同目录的会话中均可使用。
- 每条最多 2000 字，每个人格合计最多 8000 字，最多 40 条；人格总数最多 30 个。
- 关闭记忆后，从下一轮起停止向模型提供这些条目，记忆数据保留。
- 两个窗口同时修改时，旧版本提交会被拒绝，避免静默覆盖。刷新记录后核对再保存。

这一版只保存明确添加的记忆，不在后台自动提炼全部历史，不增加额外记忆模型调用。保存的条目从下一轮开始提供给 Agent。条目是参考资料，最新用户要求优先；版本、环境等易变事实仍需要核实。表单中的未保存内容不等于已记住，关闭或切换会话前请保存。

数据保存在 DSH_HOME 的 `storages/dsh-px-memory/memory.json`。使用临时文件、同步落盘及原子替换；读取损坏文件时不覆盖原件，面板显示错误，普通原生会话仍可继续。迁移机器时应与 DSH 数据一起备份，不提交到项目代码仓库。

## 长会话工作账本

“当前任务”先显示 DSH 原生 Goal 和 Team，再显示工作账本与执行证据。Goal 的暂停、阻碍、完成与自动继续状态直接来自原生服务；Team 任务显示原生编号、revision、负责人和依赖，不另外建立任务板。未启用实验性智能体团队时，Goal、账本和执行记录仍可使用。

账本保存目标、阶段进展、关键约束、决定与经验、下一步及执行证据引用。多步骤工作时，Agent 在重要进展、需求变化或遇到阻碍后通过 `task_checkpoint` 更新；也可以直接要求“保存当前工作账本”。简单问答不要求记录。

账本随原始会话工具记录保存。压缩改变模型可见历史时，PX 会重新提供最近保存的账本快照；它不依赖压缩摘要是否仍记得那份笔记。最近保存的用户要求会作为有界预览一并提供，较长内容可能截断。未保存进账本的细节仍依赖原生历史、摘要或后续读取，不能保证无限次压缩后完全无损。

`task_state` 只读原生目标、团队与任务，不唤醒成员、不恢复目标。冷会话显示持久快照，自动继续状态标为未知，不把存储记录当作运行状态。`task_review` 读取账本和执行摘要；`task_evidence` 根据真实执行编号分页读取输出，不重新运行命令。

保存账本时自动记录当前 Goal 的编号和 revision；可通过 `nativeTaskIds` 关联最多 10 项原生团队任务，宿主核对存在性并保存版本。它们仅表示保存时的归属，不代表当前状态或验收通过。记账前读取最新 checkpoint 序号可以防止覆盖已变更的记录。已有旧格式 checkpoint 继续可读。

账本不是另一套 goal、todo 或 job 调度器，也不是后台执行授权。用户新要求、原生目标和实际任务状态优先。工具“已返回”不等于测试通过；账本之后有新要求、操作、原生任务变化或团队回执时，面板提示重新核对。成员消息和“已入队”不表示任务完成；目标暂停后不能根据旧账本自行恢复。旧提交的测试结果不能证明新提交也通过。

## 项目知识与上下文观测

“打开项目知识”进入社区 [dsh-mnemon](https://github.com/omdsh-dev/dsh-mnemon) 的管理页面。默认组合只启用项目档案 Source 和 General 策略：创建和修改托管 Markdown、检索片段、按需读取全文、修订与本地归档。模型读取结果包含来源与版本；修改旧约定应更新对应文档，避免同时保留互相冲突的现行事实。

默认存储根为 DSH_HOME 下的 `storages/dsh-px-knowledge`，按规范化工作区路径隔离。不同人格可共享同一工作区资料；不同工作区不共享这套资料。原项目文件不会因建立知识档案而被修改。归档保留内容，不能当作彻底删除。备份时连同这份目录一起保留。

组合不启用 Mnemon 的常驻运行时记忆、外部 Provider、嵌入模型或自动历史提炼，不安装 Mnemon CLI。社区管理页仍可能显示未装配的可选来源，这是组合选择。用户若已单独安装 Mnemon，PX 不再加载第二个记忆 Host；其原有范围、Provider 和设置继续由用户自己的安装负责，不自动迁移或覆盖数据。

[dsh-context](https://github.com/bowenliang123/dsh-context) 作为 Pack 的独立社区成员提供上下文构成、用量和会话演变视图。它负责观测，账本负责持久工作摘要，Goal/Team 负责执行状态。已有独立 dsh-context 时保留用户自己的实例，避免重复注入。

## 更新与兼容

“记忆与知识”是独立的可选功能包。新客户端以 Pack 声明的清单管理功能包：首次出现的新功能可随升级安装，用户已经卸载的功能不会因此复活。自定义安装声明和禁用选择保留。较早的五功能包客户端需要先安装配套的新 Desktop；独立 Web 使用对应 Pack。

插件关闭不会删除记忆或账本。恢复插件后可以继续读取；未启用插件时，Agent 只使用原生 DSH 提供的上下文与工具。
