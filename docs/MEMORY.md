# 人格、经历与工作账本

在“工具 → 能力 → 人格与经历”管理会话身份、私有记忆、历史检索及知识与 Skills。PX 知识通过 Mnemon 的公开 Source 接口提供四种范围，文档修订、写入冲突、检索和归档由原生 Documents 引擎处理。

## 会话与人格

空白会话可以选择人格，开始运行后固定身份。需要另一人格时，在“用另一个人格继续”中选择目标，创建空白会话或接续会话。创建使用原生 DSH 接口，并关联原工作区；不会自动发送消息、执行任务或恢复原会话的 Goal。

原生 Team 子智能体继承并固定父会话人格；团队角色不等于另一人格。Mnemon 的委派视图继续由原生系统授权和限额，PX 补充压缩后仍可用的调用说明，并核对同人格、同项目后记录实际执行者。独立人格通过接续会话使用自己的知识。

每个人格模板有配置版本。修改名称或协作说明产生新版本，新会话采用最新版本；已有会话保持原版本，可在空闲时明确选择“本会话采用最新人格配置”。模型、推理参数、Agent 预设和操作权限仍由 DSH 控制，不随人格暗改。

人格和可见记忆在请求组装前按轮次取快照，同一工具链中不中途换身份。记忆新增、修改或关闭从下一轮的首次请求生效。归档人格保留历史和记忆，并拒绝新模型轮次；不会把原会话改成默认助手。默认助手不能归档。

## 接续会话

接续会话获得原会话的一个固定读取截止点，以及最近用户要求、助手回复、工作账本和原生状态的有界历史摘录。原会话需要已有完成的对话；正在运行时先等待或停止本轮。

可以按需读取截止点内的用户/助手文字、普通工具执行记录及 Goal/Team/Job 状态。系统提示、隐藏运行上下文、思考内容和记忆工具的复制结果不进入交接历史。原会话正文已经说出的信息仍会被分享，因此跨人格交接并不抹去正文里的私人信息。

目标使用自己的私有记忆，不继承旧人格的记忆库。截止点之后的新内容不自动开放，也不传递来源会话获得的其他交接权限。需要更新的交接范围时重新创建接续会话。已有账本和状态只是历史参考，原生任务身份、负责人、暂停和执行回执须重新核对；不复制另一套 Goal 或任务板。

## 人格私有记忆

在“人格模板与私有记忆”中明确保存约定，或要求 Agent 使用 `persona_memory` 的 read/save/forget。写入先读取 revision，过期修改被拒绝。

- **本目录**：同一人格、同一规范化目录可见。
- **此人格通用**：同一人格跨目录可见。
- 每条最多 2000 字，每个人格合计最多 8000 字、40 条；最多 30 个人格。
- 新人格从空记忆开始。关闭记忆停止模型在后续轮次的使用，数据和手动查看入口保留。
- 项目档案是同工作区共享资料，不会因改变人格而隐藏；人格私有记忆与它分开存储。

人格模板、版本和会话绑定保存在 DSH_HOME 的 `storages/dsh-px-memory/memory.json`。已绑定的旧格式条目可读取为固定绑定；未绑定的旧会话在打开时使用默认助手。本功能不扫描并推断旧会话历史上曾经使用过哪些人格。

## 经历与历史检索

`persona_history` 和“本人格的经历与历史”共用只读查询：

| 操作     | 用途                                                   |
| -------- | ------------------------------------------------------ |
| sessions | 查看可读会话的主题、最近助手回复与状态原文摘录         |
| search   | 按关键词查询对话、工具返回、工作账本和原生状态         |
| read     | 按来源会话、事件编号和字符位置读取原文；长内容分段返回 |

只有同人格会话和当前会话明确获得的交接范围参与查询。索引通过原生只读句柄读取会话，不启动 Agent、不运行原工具。后台索引是本机数据处理，不调用额外模型；经历目录是原文摘录，不是自动提炼后的已确认知识。

中文短词使用字面匹配，较长关键词使用本地全文索引；多个词用空格分隔。默认界面限制本项目，可取消以查找本人格其他项目的历史。目录最多显示最近 100 个会话，单次关键词检索最多 20 条；缩小关键词或打开原会话可进一步核对。

首次索引较长历史可能分多次完成，查询返回已覆盖会话数、未完成状态及读取错误；再次查询会继续推进。存储故障不能当作“从未讨论过”。历史文件和工具结果可能包含过时内容；助手描述、工作账本、工具返回和原生状态分别标注，不据搜索命中宣称当前事实或验收通过。

`history.sqlite` 是可重建缓存，原始会话由 DSH 持久化。识别到索引损坏时重新建立缓存；缓存不可用不会修改原始记录。停用本插件后，原生会话功能保持其自身行为。人格分区是检索与注入范围，不是限制同机全文件权限 Agent 的操作系统沙箱。

## 长会话工作账本

“当前任务”显示原生 Goal/Team、工作账本和执行证据。`task_state` 只读原生目标和团队，不唤醒成员或恢复目标；冷会话自动继续状态标为未知。`task_review` 读取账本与执行摘要，`task_evidence` 分页读取已记录输出，不重跑命令。

多步骤工作中，通过 `task_checkpoint` 保存目标、进展、约束、决定、下一步和证据。保存时记录原生 Goal 的编号/revision，也可关联最多 10 项原生团队任务。它们表示保存时的归属，不代表当前状态或验收通过。

账本从原始工具记录恢复，不依赖压缩摘要是否仍记得它。未记录的细节仍须通过历史检索或原始文件找回，不能保证无限次压缩无损。用户新要求、原生任务变化和新的操作会使旧账本需要重新核对。工具正常返回也不等于测试通过。

## 知识、纠正与共享

| 范围        | 谁能找回                 |
| ----------- | ------------------------ |
| 人格私有    | 此人格的全部项目         |
| 人格 × 项目 | 此人格在当前项目中的会话 |
| 项目共享    | 当前项目的所有人格       |
| 全局共享    | 全部人格与项目           |

知识存于 DSH_HOME 的 `storages/dsh-px-knowledge-scopes`，每个范围使用独立的 Documents 数据目录。范围是检索与注入边界；拥有全文件权限的 Agent 仍可读取本机文件。

在“知识与 Skills”选择范围后新建或搜索主题。同一范围内的同名主题会更新原文及版本，不另建一条“新版主题”。保存前读取字符串存储版本；他人修改后拒绝过期保存，重新读取并检查差异后再提交。编辑草稿按当前入口、会话与人格保留；草稿不表示已写入知识库。

共享会复制一个明确版本，保留来源版本和摘要；不会自动把整个人格私有库开放。来源被纠正、归档或消失后，共享副本及其再次分享的副本不再作为当前结论返回。需要查看旧依据时显式选择历史读取；不会把历史正文默认为当前知识。归档保留原文，不等于永久删除。

可关联项目文件的原生版本。文件改变、删除或无法核实时，知识标为需要重新核对。**文件版本未变只证明来源未变，不证明知识结论确实受该文件支持**。记录区分用户提交、模型写入和旧记录的未知作者；仍须判断原文是否支持结论。

默认配置使用 General 策略和 PX 知识，原 Mnemon 项目档案保留手动入口，避免自动重复注入。0.6 首次采用该默认装配后，后续用户更改不反复覆盖；用户自行安装的 Mnemon 保留原配置。独立 Web 用户可在 Mnemon 原生配置页选择相同组合。未默认开启外部 Provider、嵌入模型、后台自动提炼或闲时复盘。

模型通过原生 `mnemon_view_route` 和 `mnemon_view_action` 按本轮提供的路由使用知识；资料正文按需读取，不整库常驻。目录即使为空也返回写入版本。`visible` 合并可见范围；明确要求保存某一主题时，只读取该范围、写入并按需回读，避免反复搜索。没有 Source 时不能从“工具已安装”推断知识可用。

## Skills

Skills 页读取原生技能目录。第三方、项目已有技能可查看；只有 PX 管理的 `SKILL.md` 提供编辑和启停，避免覆盖第三方文件。项目技能保存到最近 Git 根目录的 `.dsh/skills`（没有 Git 根则使用会话目录）；全局技能位于 DSH_HOME 的 `skills`。保存前显示实际位置，目录变化或文件版本冲突时要求重新读取。

启停使用原生 `disable-model-invocation` 和 `user-invocable` 字段。保存后等待原生目录刷新；“等待发现”不等于保存失败。Skills 是可复用操作说明，不能替代执行权限、任务授权或成功回执。

技能保存遵守当前会话的原生文件权限。全局目录或 Git 根不在允许写入范围时，先选择可写的项目目录，或由用户在会话访问模式中明确授权；界面不会自动扩大权限，拒绝写入后保留草稿。

## 长周期使用与限制

账本保留进展，Goal/Team 保存执行状态，知识保留可复用结论，人格保存协作偏好。压缩摘要和迟到的成员消息都是待核对的历史信息；重启后按原任务 ID、版本与原始回执接续，不因消息重投而重跑已结算操作。

优先使用有界目录、关键词检索及精确原文读取。当前不默认提供向量语义检索或自动判断两种措辞是否矛盾；纠正依靠明确主题和修订，语义冲突需人工或模型核对。dsh-context 展示实际上下文和用量；测试中的降低压缩阈值只提高压缩频率，不改变模型真实窗口或保证无限会话无损。
