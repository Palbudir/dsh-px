# DSH-PX

DSH-PX 是面向 Windows 本机工作的 Agent 插件整合包，基于 DeepSeek Harness（DSH）的原生插件架构。多个自制与社区插件组成一套工作能力，通过两种形式发行：

- **DSH-PX Pack**：提供基础组件与七个功能包的组合交付物，锁定配套版本；也保留原生聚合 bundle 供 `dsh web` 安装。
- **DSH-PX Desktop**：以锁定版本的官方 Desktop 源码为基础构建的 Windows 客户端，随安装提供基础组件，自动安装配套的七个功能包。

> 本项目为第三方客户端，与深度求索（DeepSeek）无从属、合作或授权关系。品牌与依赖说明见 [NOTICE.md](NOTICE.md)。

## 使用

可下载安装的版本以 [GitHub Releases](https://github.com/Palbudir/dsh-px/releases) 为准：`desktop-v<版本>` 为 Desktop 安装程序，`pack-v<版本>` 为 Pack 归档，`v0.1.0-beta.re.*` 为旧客户端。模型访问需要自行配置提供商和凭据，具体项目仍可能需要 Git、包管理器或语言运行环境。

1. 安装并打开 DSH-PX Desktop，按欢迎页配置模型提供商。
2. 添加本机项目文件夹，新建会话并描述任务。
3. 按提示审阅工具权限，在文件、终端、执行记录及文件变动面板检查结果。

Pack 也可以通过原生插件管理器安装到 `dsh web`。**设置 → 运行与帮助**显示当前连接、依赖和网页读取诊断；**设置 → DSH-PX 版本**显示 Pack 版本并检查签名更新清单。

“插件”列表分别管理**文件与终端、执行记录、产物、引用与批注、定时任务、人格与记忆、电脑操作**。基础组件在**设置 → 内置插件 → 全局插件**中查看。功能包停用或卸载后，其业务数据保留，后续启动不会强行恢复用户删除的功能包。

**人格与记忆**提供每个会话的角色选择，各人格独立保存职责说明和记忆。可以在面板编辑，也可以明确要求 Agent 记住或忘记；改动从下一轮生效，不改变模型和权限。**执行记录**中的工作账本保存目标、约束、阶段进展、决定与下一步，后续调用重新提供最近快照，帮助长会话在压缩后继续工作。使用方法与范围见 [人格、记忆与工作账本](docs/MEMORY.md)。

**电脑操作**默认关闭。在它的面板中开启后，Agent 可以操作本机 Windows 应用，以及独立浏览器、PX 专用浏览器或经 Playwright 扩展接管的 Edge。每个应用和登录态网站首次使用前都会询问；删除、发送、付款等动作需要再次确认；终端、密码管理器、安全软件和 DSH 自身始终不能操作。面板显示操作记录，并可随时停止。详见 [电脑操作](docs/COMPUTER-USE.md)。

在已保存的用户或助手消息中选中一段文字，点击**批注**，在原句旁写下意见，再点**加入对话**（或 Ctrl+Enter）。只需引用时，直接点**添加到对话**。输入框中显示紧凑的“1 条批注”标签，多条批注合并计数，不展开原文或内部标识。点击标签可预览、编辑、逐条移除或全部移除；修改仅影响待发副本。正文保留，由你发送，不打开侧栏。按 Esc 或点击浮层外可收起；本窗口重新选中同一原句可继续未完成的批注。已保存的内容在“引用与批注”侧栏管理。待发附件保存在当前客户端或浏览器的本地存储，刷新会恢复；清理浏览器数据或换入口后可能需要从历史批注重新添加。每组最多 20 条。发送时原句和意见才展开交给 Agent；已发送消息沿用 DSH 的正文展示。支持 Markdown 加粗、链接、行内代码等呈现差异；跨消息选区和未完成的流式回答暂不支持。特殊渲染或超长格式化消息无法对应正文时，可通过消息下方“引用 / 批注”调整选区。

Desktop 提供 **应用 → 在浏览器中打开**，浏览器连接当前服务，使用同一份历史和插件数据。需要命令行时，在 **应用 → 管理 dsh 命令**中安装或修复入口，再打开新终端运行 `dsh --version`。该命令使用 Desktop 随附运行时，默认数据目录也是 `.dsh-px`，显式 `DSH_HOME` 仍优先。管理桌面插件使用 `dsh plugin --profile desktop ...`；如需独立启动 `dsh web`，应指定另一个数据目录并安装 Pack，不与正在运行的 Desktop 共写数据。

## 与旧客户端的关系

旧版 DSH-PX（`v0.1.0-beta.re.*`）是另一套已停止开发的 Electron 外壳，继续按原方式使用，不会收到新产品的更新。新 Desktop 使用独立的应用身份、安装目录和数据目录（`%USERPROFILE%\.dsh-px`），两者可以并行安装。历史版本与资产保持不变。旧会话副本导入步骤见 [数据导入](docs/IMPORTING.md)。

确认新版可用后，可在 Windows“已安装的应用”卸载旧 **DSH-PX**，保留 **DSH-PX Desktop**。退出前先结束旧版任务，备份 `%APPDATA%\dsh-px`；旧卸载器询问是否删除本地数据时选择“否”。旧会话和配置不会因安装新版而自动导入，不要直接覆盖新版数据目录。

## 更新与数据

在 **应用 → 检查更新**或**设置 → DSH-PX 版本 → 下载与安装更新**中分别更新客户端与整个 Pack。Pack 下载量约 8 MB，包含基础组件和七个功能包；客户端优先按 blockmap 下载变化的数据，缺少旧安装器、索引或校验失败时回退完整下载。从旧更新器首次升级仍需完整安装包，之后符合条件的升级才可差分。

整个 Pack 独立更新自 Desktop 0.3.3 提供。升级到 0.4 时先更新 Desktop，以支持新增的人格与记忆功能包；之后同代际 Pack 可继续独立更新。首次建立约 370 MB 的可重建运行缓存；普通插件更新复用未变化的宿主文件，DSH 核心变化时重建。下载完成后由你确认重启，沿用原生任务检查与停止流程。启动未完成的 Pack 会在下次启动回退到此前组合；已有会话、凭据、用户插件与禁用选择保留。独立 `dsh web` 仍通过原生插件管理器更新。

点击安装后，确认框显示在主窗口中；主窗口收在托盘时会先被调出。客户端更新依赖 Windows 安装登记（`HKCU\Software\77968efd-2ef8-565e-9082-8a54e960920f` 的 `InstallLocation`）：登记缺失或指向其他目录时，客户端在退出前取消安装，并给出修复命令。请从开始菜单或桌面快捷方式启动客户端后再更新；由其他打包应用（例如 Codex 桌面版的自动化操作）启动的客户端，其安装器写入的注册表可能被重定向，导致登记不完整。

更新诊断默认写入 `%APPDATA%\dsh-px-desktop\logs\updates`，安装器阶段日志位于 `%LOCALAPPDATA%\dsh-px-desktop-updater\installer-logs`，失败时记录安装器给出的原因，下次打开更新窗口会提示。安装器等待旧进程退出最多 60 秒；静默安装失败时始终弹出说明，并在登记有效时重新打开原客户端。日志帮助定位故障，不保证所有异常都能自动恢复。

模型、会话、凭据与插件业务数据保存在 `%USERPROFILE%\.dsh-px`。卸载 Desktop 时始终保留这个目录，安装器不提供删除选项；需要清理时请先备份后手动处理。界面缓存（`%APPDATA%\dsh-px-desktop`）和更新下载缓存会随卸载删除，其中不含会话与凭据。不要将凭据、会话或项目文件放入发布包。

## 开发

需要 Node 24 或更新的兼容版本、npm 和 Git。

```powershell
npm ci
npm run build
npm run test
```

提交与检查见 [CONTRIBUTING.md](CONTRIBUTING.md)，产品与版本边界见 [EDITIONS.md](docs/EDITIONS.md)，构建结构见 [PACKAGING.md](docs/PACKAGING.md)，发布门禁见 [RELEASING.md](docs/RELEASING.md)。

## 范围

当前面向 Windows 本机使用，不承诺跨平台安装、远程多人服务或云端常驻。安装程序未进行 Authenticode 签名，系统可能要求确认安装；更新清单另有 PX 的 Ed25519 签名，两者不是同一种签名。用户自行添加的第三方插件可能需要 pnpm、网络或额外运行环境。

旧 Pack 中的社区插件 dshmarket、dsh-mermaid-render 与 dsh-find-plugin 首发不随 Pack 提供，后续逐个迁移到原生宿主接口；需要时可通过官方插件管理器自行安装。文件版本保护、工具权限与原生网络限制仍由 DSH 执行。
